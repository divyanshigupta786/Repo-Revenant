# RepoRevenant: Architecture Specification

## Overview

RepoRevenant is an open-source, evidence-backed software investigation and repository resurrection platform. Its core architecture separates presentation, deterministic static analysis, neural model inference, and sandboxed execution.

## 1. Epistemic Hierarchy

The system strictly divides information into explicit epistemic categories:
1. **Observed Facts**: AST parse outputs, file listings, test runner exit codes.
2. **AI Hypotheses**: Probable explanations generated by open-weight models regarding why the codebase rotted.
3. **Proposed Repairs**: Targeted unified diff modifications awaiting human review.
4. **Human-Approved Changes**: Patches consented to by the developer.
5. **Executed Verification Checks**: Subprocess tests executed in isolated sandboxes with scrubbed environments.
6. **Verified Outcomes**: Only tests exiting with code 0 in the sandbox declare resurrection.

## 2. 7-Stage Investigation Pipeline

1. **Stage 1: Intake (`backend/app/engine/intake.py`)**
   - Validates Git URL or sample identifier.
   - Blocks private IP ranges (SSRF protection against `127.0.0.1`, `10.0.0.0/8`, `169.254.169.254`).
   - Copies code into an isolated temporary workspace directory.

2. **Stage 2: Inspection (`backend/app/engine/inspector.py`)**
   - Discovers directory hierarchy, calculates lines of code.
   - Detects project languages and test frameworks (`pytest`, `unittest`).
   - Parses manifest files (`requirements.txt`, `pyproject.toml`).

3. **Stage 3: AST Forensics (`backend/app/engine/analyzer.py`)**
   - Parses Python files into Abstract Syntax Trees using Python's native `ast` module.
   - Flags removed standard library modules (PEP 594: `imp`, `cgi`, `pipes`).
   - Flags abstract collections drift (`collections.Mapping` vs `collections.abc.Mapping`).
   - Flags Python 2 syntax drift (print statements).

4. **Stage 4: Baseline Verification (`backend/app/engine/verifier.py`)**
   - Executes the test suite in an isolated sandbox before applying any patch.
   - Records pre-patch failures, exit codes, and durations.

5. **Stage 5: AI Diagnosis (`backend/app/engine/ai_agent.py`)**
   - Packages AST findings, source code snippets, and baseline test failures into a bounded evidence prompt.
   - Queries local open-weight model (or fallback to built-in deterministic expert engine).

6. **Stage 6: Patch Synthesis (`backend/app/engine/patcher.py`)**
   - Synthesizes minimal unified diffs.
   - Validates that post-patch code parses cleanly with `ast.parse` before saving.

7. **Stage 7: Sandboxed Verification (`backend/app/engine/verifier.py`)**
   - Applies patch in disposable workspace.
   - Re-runs test suite under clean environment.
   - Verifies exit code 0 and all assertions passing.

## 3. Database Persistence

All state is stored in SQLite (`reporevenant.db`):
- `investigations`: Primary metadata, health score transitions, duration, status.
- `findings`: AST findings, line numbers, detection methods, evidence.
- `patches`: Unified diffs, original code, proposed code, approval statuses.
- `test_runs`: Execution commands, exit codes, stdout, stderr, test counts.
- `timeline_events`: Timestamped forensic telemetry stream.
